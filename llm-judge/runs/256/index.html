Send Cypress Accessibility and UI Coverage results anywhere with webhooks
October 7, 2026
3 min read

Your Accessibility and UI Coverage reports already tell you a lot. The harder part is getting that information in front of the right people at the right time.

Starting today, Cypress Cloud webhooks can send two new events when a report finishes processing:

run.accessibility.completed for Cypress Accessibility
run.uiCoverage.completed for UI Coverage

They join the existing run.completed event. You choose which events each webhook receives, and Cypress Cloud sends a signed JSON POST to your endpoint as soon as the report is ready.

Why we built this

Many teams asked us for the same thing: a way to react to a report without watching a CI job or polling Cypress Cloud. Webhooks start the work from the report itself, so a score can reach a dashboard, a chat channel, or a triage script the moment it exists.

What you can do with it

Post your accessibility results to Google Chat. The Cypress Accessibility payload includes the project name, branch, score, violation counts by impact, and a reportUrl that links back to the detailed report with full-page snapshots for every issue. A receiver such as a Google Apps Script web app can turn those fields into a message your team sees right away.

Triage reports before you spend time on analysis. The payload tells you when processing failed or when a report is partial, and it summarizes the score and violations. Your receiver can decide which reports deserve a closer look, then pass the run URL to the Cypress Cloud CLI or Cypress Cloud MCP for details.

Add scores to your engineering dashboards. Send them to Cortex, Datadog, or another internal system and track UI Coverage and accessibility health next to the quality signals you already watch.

Track metric drift. The UI Coverage payload includes the coverage score, tested and untested element counts, tested and untested link counts, and the number of views covered. Alert on a drop, or chart the trend per branch/tag over time.

Set it up in a few minutes

You need to be an Owner, Admin, or Team Admin of your Cypress Cloud organization (or request one to do this step), and you need a publicly reachable endpoint that accepts POST requests.

Open your project, then go to Settings > General and find the Webhooks panel.
Click Add webhook.
Enter your Payload URL, set a signing secret, and select run.accessibility.completed, run.uiCoverage.completed, or both.
Click Send test to deliver a sample payload and confirm your endpoint works.

Don't want to host a receiver? Point the Payload URL at Zapier, Make, n8n, Jira automation, PagerDuty, or Slack Workflow Builder, and map the fields there.

Get started
Read the Cypress Cloud webhooks documentation for setup, payload fields, signatures, and retries.
See the Cypress Accessibility webhooks guide for example workflows.
