Find elements the way your users do with cy.getByRole()
October 14, 2026
11 min read

Starting in Cypress 16.2.0, cy.getByRole() is a built-in query that finds elements by their role and accessible name. The role is what a screen reader announces an element as, such as a button or a link, and the accessible name is the text it announces for it.

This offers a built-in alternative to the .findByRole() selector from the popular Cypress Testing Library plugin. That package no longer has an active maintainer and the previous maintainer suggested Cypress build these queries into Cypress directly.

We agree with that direction. Role-based queries are a core way to write resilient, accessible tests, and they belong in Cypress itself. cy.getByRole() is the first of these built-in queries. We plan to bring more of the Testing Library queries teams depend on into Cypress.

What cy.getByRole() does

cy.getByRole() finds every element with a given role, such as button, link, heading, or tab, and can narrow the results to elements whose accessible name matches. Because those are what assistive technology announces, a test written this way finds elements the way assistive technology does. If a control’s role or label changes, the test fails.

describe('account settings', () => {
  it('saves profile changes', () => {
    cy.visit('/settings')
    cy.getByRole('textbox', { name: 'Display name' }).type('Jane Doe')
    cy.getByRole('button', { name: 'Save changes' }).click()
    cy.getByRole('alert').should('have.text', 'Changes saved')
  })
})

A few behaviors on how cy.getByRole() works:

It yields every match. Like cy.get(), cy.getByRole() yields all matching elements in document order. Narrow the name, or chain .first() or .eq(), to act on one.
A string name matches the whole name, case-sensitively. Pass a regular expression to match part of a name or ignore case, or a function for custom logic.
It skips elements hidden from the accessibility tree by default, such as elements with aria-hidden="true" or display: none. Pass hidden: true to include them.
It retries like any Cypress query, so it waits for an element to appear and for chained assertions to pass.
It prefers built-in HTML elements. If a native HTML element exists for a given role, cy.getByRole() matches that element only, unless native: false is passed.

To narrow by state, such as checked, selected, expanded, or heading level, chain .filter():

// The tab that is currently selected
cy.getByRole('tab').filter('[aria-selected="true"]')

// Level 2 headings
cy.getByRole('heading').filter('[aria-level="2"], h2:not([aria-level])')

// A checked native checkbox
cy.getByRole('checkbox').filter(':checked')

// A checked checkbox that gets its role from a role attribute
cy.getByRole('checkbox', { native: false }).filter('[aria-checked="true"]')

// The menu button whose menu is open
cy.getByRole('button').filter('[aria-expanded="true"]')

// A toggle button that is switched on
cy.getByRole('button').filter('[aria-pressed="true"]')

// The link to the page the reader is on
cy.getByRole('link').filter('[aria-current="page"]')

// Every button except disabled ones
cy.getByRole('button').not(':disabled, [aria-disabled="true"]')

The cy.getByRole() API reference covers every option, including shadow DOM, TypeScript, and scoping with .within().

Why native elements are the default in cy.getByRole()

For any role that HTML has a native element for, such as button, link, heading, dialog, or checkbox, cy.getByRole() matches only elements whose tag gives them that role. A <div role="button"> does not match cy.getByRole('button') unless you pass native: false.
