Red-teaming in AI safety is a structured process where people deliberately try to make an AI system behave in harmful, unsafe, or unintended ways—before real users or adversaries do. The goal is to find weaknesses, then fix or mitigate them.

In practice, AI red-teaming can include:

- **Adversarial prompting** – trying to bypass safety filters or get the model to produce disallowed content.
- **Jailbreak attempts** – testing whether the model follows harmful instructions despite its guidelines.
- **Bias and fairness probing** – checking whether the model produces discriminatory or unfair outputs.
- **Privacy testing** – seeing whether the model leaks training data or private information.
- **Robustness testing** – evaluating behavior under unusual, conflicting, or manipulative inputs.
- **Policy-violation testing** – checking outputs against safety, legal, and ethical policies.

Red-teaming is often done by internal safety teams, external experts, or crowdsourced testers. The results are used to improve model training, add safeguards, update usage policies, and build better monitoring systems.

In short: red-teaming is “attack your own system to make it safer.”

import re

def validate_input(user_input):
    """Test input validation mechanisms"""
    # Check for suspicious patterns
    dangerous_patterns = [
        r"['\"]",           # Quotes
        r"--",              # SQL comments
        r";",               # Statement termination
        r"OR\s+1=1",        # Common injection pattern
        r"UNION\s+SELECT",  # UNION-based injection
        r"DROP\s+TABLE",    # Destructive commands
    ]
    
    for pattern in dangerous_patterns:
        if re.search(pattern, user_input, re.IGNORECASE):
            return False, f"Blocked pattern: {pattern}"
    
    return True, "Input accepted"

# Test validation
