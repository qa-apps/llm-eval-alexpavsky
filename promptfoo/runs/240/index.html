Red-teaming in AI safety is a structured process where a team deliberately tries to make an AI system fail, produce harmful outputs, or behave in unintended ways. The goal is to find vulnerabilities before real-world users or adversaries do.

Key points:

- **Adversarial mindset**: Red-teamers act like attackers or careless users, using prompts, jailbreaks, or edge cases to test the model’s limits.
- **Scope**: It can cover safety issues (hate speech, violence, self-harm), security issues (prompt injection, data leakage), and reliability issues (hallucinations, bias, or failure under distribution shift).
- **Output**: Findings are used to improve the model, add safeguards, update policies, or create better evaluation benchmarks.
- **Who does it**: It can be internal teams, external experts, or automated tools that generate adversarial test cases.

In short, red-teaming is “testing the AI by trying to break it” so that developers can fix problems before deployment.
